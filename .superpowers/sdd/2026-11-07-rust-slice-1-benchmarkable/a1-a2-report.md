## What changed

**A1 — `/metrics` + registry** (`crates/omni-gateway/src/telemetry.rs`)
- Port of `telemetry/registry.ts` + `render.ts`: the 17 series in `DEFINITIONS` order, same
  help/type lines, label sets in first-write order (a repeated key keeps its first position and
  last value), escaping (`\`, `\n`, `"`), the 13 bucket bounds and their `le` spellings, number
  formatting (`String(value)` through `jsjson::write_number`, `+Inf`/`-Inf`/`NaN`), the cap
  (`OMNI_METRICS_MAX_SERIES`; raw series are counted, past the cap a new raw series carrying
  `api_key_id` folds to `"other"`, and each raw series counts one `omni_metrics_series_folded_total`
  the first time it folds), and empty metrics omitted.
- Hot path: no lock. A write resolves its raw series through an immutable `ArcSwap` index, then
  updates atomics (f64 bits CAS-add, histogram per-bucket counters summed at render). The mutex
  is taken only to create a series, or for one created since the index was last republished, and
  by a scrape. A raw series' resolution never changes once made, so caching it is exact.
  The label key is built in a thread-local buffer, with no per-write allocation on the cached
  path, and the index is a `foldhash` map.
- Recording, gated on `OMNI_METRICS_TOKEN` as in TS (`metricsEnabled`):
  `omni_build_info{version}` at boot (`OMNI_CLI_VERSION` at build, else `OMNI_VERSION`, else
  `0.0.0-dev`); `record()` in the Finisher, the one site that completes a row, i.e. `finishLog`
  (requests/duration/ttft/tokens×4/cost); `omni_upstream_duration_seconds` from a new
  `onResponseHead` hook on the Rust HTTP client (whole ms of wall clock, as `now()-startedAt`);
  `omni_breaker_open` from `persist_health` (inside the apply step, as TS's `updateHealth` callback);
  `omni_ratelimit_rejected_total` on `admit` and `consume` refusals; `omni_inflight` from the
  load registry's new per-provider counts (`localCounts`, `Map` insertion order) at scrape;
  `omni_stream_*` 0/0/0 and `omni_coord_*` 0/0 set at scrape (no sockets, in-memory coord),
  exactly as TS reports them for this shape. `omni_otlp_spans_dropped_total` is registered but
  never written (OTLP is A13; config still parsed, nothing exported).
- Route: `GET|HEAD /metrics` only when the token is set (otherwise TS's 404 catch-all), exactly
  `Bearer <token>` compared in constant time over equal lengths, bare 401 otherwise, and
  `text/plain; version=0.0.4; charset=utf-8`.

**A2 — static serving + plugins** (`crates/omni-gateway/src/static_files.rs`, `server.rs`, `lib.rs`)
- Routing now matches `new URL(request.url).pathname` as Elysia does: dot segments (including
  `%2e` spellings) resolved, `\` read as `/`, the WHATWG path percent-encode set applied. Plain
  paths (every `/v1/*` call) borrow the request path with no allocation.
- The `/*` catch-all as `app.ts` defines it: `%2f`/`%5c` → 404; `decodeURIComponent` (a throw →
  404); `/api`, `/v1` and their subpaths → 404; `/` → `index.html`; lexical containment, then
  `realpath` containment (symlink escapes → 404); a regular file of size > 0 is served with
  `public, max-age=31536000, immutable` under `/assets/`, else `no-cache`; content type
  `text/html` for a real path ending `.html`, else `Bun.file().type`; otherwise the SPA fallback,
  only for `accept` containing `text/html` and not `/assets/*`, and only if `index.html` is non-empty.
- Bun-runtime behaviours reproduced: `content-disposition: filename="…"` for the types Bun adds it
  to; single-range `Range` (206/416, multi-range and malformed headers → whole body, `If-Range`
  present → whole body); HEAD with `content-length` and no `date`, and no `content-disposition`;
  a path that resolves to a directory → Bun's production 500 (`Something went wrong!`). `date` is
  now stamped by the server on every non-HEAD response, as Bun does; hyper's own `date` is off.
- Content types come from `crates/omni-gateway/data/static-mime.tsv`, generated by
  `conformance/vectors/static-mime.ts` from the Bun 1.4.4 runtime itself: `Bun.file().type` for all
  1184 extensions Bun knows (key list `bun-mime-extensions.txt`, from the pinned Bun source), plus
  a live `Bun.serve` per type for the disposition rule. It self-checks against `/etc/mime.types`,
  and `--check` reports drift.
- Directory: `OMNI_STATIC_DIR` is taken literally. Otherwise `<exe dir>/public`, then the checkout's
  `apps/dashboard/dist`, matching TS's two candidates relative to its bundle. Logged as TS logs it
  (`dashboard directory resolved|absent path=`). It is resolved with `realpath` once at boot. Disk
  is touched only on the catch-all (blocking threads); `/v1/*`, `/health` and `/metrics` never reach it.
- Plugins (spec non-goal): no plugin code is read or run. At boot, one `WARN plugin skipped
  plugin=<id> reason="plugins are not supported in this release"` per directory in
  `$OMNI_ROOT/plugins` (else beside the DB), sorted, symlinks not followed; then TS's
  `plugins resolved count=0 path=`. `/api/plugins` and `/api/plugins/*`, any method → 501
  `{"error":{"code":"UNSUPPORTED","message":"plugins are not supported in this release"}}`.
  `/plugin-assets/:id/*` → TS's own `no such plugin asset` 404 (no plugin is loaded).

## Concerns

1. 501 code string: the spec says "HTTP 501 with the usual error body" but names no code;
   `UNSUPPORTED` follows the horizontal-scaling spec's vocabulary. A one-line change if the controller prefers another.
2. Directory → Rust always gives Bun's *production* 500. TS without `NODE_ENV` (Dockerfile, run.ts) shows the dev stack page,
   which leaks the cwd; deliberately not reproduced.
3. Default static dir without `OMNI_STATIC_DIR` is relative to the executable (no bundle dir in Rust); embedding `dist/` (optional) not done.
4. Long-window rate-limit debits lag a row commit by one writer batch (slice 1, accepted). The surface driver
   waits 400 ms between traffic requests so a `tokens:5h` refusal lands where TS's does; at 30 ms the
   second request was admitted. This is a pre-existing gateway timing property, not a metrics difference.
5. `omni_inflight` is set from per-provider load slots at scrape. In-flight streams at scrape time were not
   compared black-box (TS and Rust hold slots for different instants); a unit test pins the `Map` order.
6. hyper 400s on `<`, `>`, `` ` `` in the request-target (and, probed, on a raw non-UTF-8 byte such as 0xFC), where Bun rewrites and serves them (pre-existing, recorded). UTF-8 `/ü` compares equal.
