## Important — R1: raw cursor extraction introduces a strict-text failure

- **Location:** `crates/omni-store/src/logs.rs:142`; shared by `page_encoding` at `:56` and export. `r.get::<_, Value>` strictly decodes SQLite TEXT as UTF-8, whereas row JSON uses lossy conversion. It is performed at `index == limit` even when there is no next page.
- **Concrete reproduction:** seed 501 rows `x000001`…`x000501`, `at=100.5`, `requested_model='m'`, `status=200`, `duration_ms=1`; replace `x000002`'s ID with `CAST(x'ff' AS TEXT)` and set its `at=99`; set `x000001`'s `at=98`. The malformed ID is row 500.
- As admin or viewer, request `/api/logs/export?since=0&until=9007199254740991&format=jsonl` (also CSV), or `/api/logs?limit=500`. **TS: 200, 501 export rows / 500 logs. Rust: 500 `{"error":{"code":"INTERNAL","message":"internal error"}}`.** Anonymous remains 401; process survives.
- Evidence: `/tmp/opencode/a7-review/r1/probe-utf8.log`, `probe-utf8/probe-utf8-{ts,rust}.json`; six response mismatches plus six expected-status failures. This is introduced by this range, not the earlier public-cursor safe-integer check.
- Fix: derive internal binding values using the same Bun-compatible conversion as TS, including lossy UTF-8 and JS numeric rounding, retaining BLOB/NULL types. Avoid strict cursor extraction on interactive pages. Add boundary tests for both routes and an exactly-full final page. Merely preserving arbitrary raw SQLite bytes is not necessarily TS-equivalent: TS rebinds its decoded row values.

## Minors / scope qualifications

- **M4 — usage/log opening can escape the four-permit lifetime:** `crates/omni-gateway/src/admin_routes.rs:125-139`. The permit stays in the async future while `spawn_blocking(open_reader)` owns only path/offset. Drop that future while its blocking open is queued/running: the permit releases immediately, but the opener still runs and may open a connection. Repeated cancelled opens can therefore exceed four transient openings; actual query execution retains its permit correctly at `:150-158`. Move the permit into the opening task and return it with the store. This cancellation interleaving is established by code inspection, not a timed HTTP reproduction.
- **Nodes remains on control:** `admin_routes.rs:339-345` has no `reader().await`, unlike logs/usage. It remains coupled to config operations and bypasses the read-lane bound. No wrong node response observed; adjust the implementation or the claimed lane scope.
- **Reader pragmas differ:** `omni-store/src/lib.rs:90-101` sets READ_ONLY and the same 5000ms busy timeout, but not main connection `foreign_keys=ON` / `synchronous=NORMAL` (`migrate.rs:132-139`). WAL mode persists in the database. Those two differences do not affect these SELECT-only paths, but “same pragmas” is inaccurate. READ_ONLY prevents main-database writes; it is not a general sandbox prohibiting temp databases/ATTACH if future code adds SQL.
- **Framing self-check gap:** `conformance/e2e/admin-routes.ts:279-285` verifies chunk lengths but skips checking each trailing CRLF (and the final CRLF bytes). A body `1\r\naXX0\r\nYY` is accepted as complete. Tighten delimiter checks; normal Hyper/Bun output passed.

## Pool, consistency and memory assessment

- Export acquires a permit before spawning and moves it into the blocking task. `ExportLease::drop` returns the connection before releasing the permit, including SQL errors and unwinding; open failure drops the captured permit. A dropped response future cannot cancel a started blocking page, but that page owns its lease until it finishes. No lease/permit spans socket backpressure. No lost pooled connection/permit path found.
- `query_map(...).collect()` finishes or drops its iterator before return; rusqlite `Rows::drop` resets the statement, including errors. Cached statements retain compiled SQL, not a live read transaction. A page is one SQLite SELECT/snapshot, including its sentinel. Different pooled connections on later pages introduce no stronger inconsistency than TS's independent page reads.
- Reused statements rebind parameters and SQLite handles schema invalidation. Readers open after boot migration; fresh usage/log handles see committed writes. These GET handlers do not themselves perform an earlier write, and authorization precedes lane entry. No stale settings/migration read identified in normal file-backed operation.
- Both semaphore queues have **no finite waiter-count/time limit**. Pending futures retain request/query state; cancellation while awaiting a semaphore removes the waiter and holds no connection. Four active tasks is not a bound on total request memory. Outbound idle-timeout disparity is accepted as the separate all-response roadmap item; per-page leasing correctly prevents stalled sockets monopolizing permits.
- Export boundary tests passed for empty, NULL, BLOB and Unicode IDs placed at row 500; long IDs/fractional timestamps and >500 equal timestamps also passed. Text/NaN-like timestamps and integers above the safe export bound were excluded by the required numeric range in both gateways, not artificially traversed. No repeat/nontermination observed on these fixtures. R1 blocks the invalid-UTF8 boundary case.
- Concurrent-write experiment: while reading a 60k-row export, delete the oldest unseen row and insert one older and one newer than the current cursor. Both return exactly 60k unique IDs, omit the deleted/newer rows and include the older insert; exact ID sequences equal (`mutation.log`). Continuous matching insertions can extend either implementation indefinitely, as before.
- Usage unusual labels included quote/newline, invalid UTF-8/surrogate-byte sequences, NULL and BLOB; measures included nonfinite values, negative zero, >2^53 and text. JSON bytes equal. Lone UTF-16 surrogates cannot survive SQLite UTF-8 binding as lone surrogates; their replacement behavior is what is compared. Empty/one-bucket answers and aggregate overflow were also exercised.
- `usage_json` appends to a local string and propagates every row error; control discards the string on error, and HTTP builds 200 only after success. No partial 200 can escape even if an error occurs after earlier rows. The overflow unit case fails at the first step; mid-read error safety is a control-flow inspection, not a fault-injection test.
- Memory evidence: five fresh processes per implementation/phase, identical 300k-row/70k-bucket fixture and three answers, separate default/purge=1 batches, VmHWM, all comparisons completed. This controls important allocator/high-water confounders and supports the large reduction reported; it does not establish a hard memory cap. No repeated memory measurement requested or performed.
