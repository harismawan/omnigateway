## Important findings
**R1 — BLOB credential ids disclose rows that frozen TS omits (normal schema).** `crates/omni-control/src/client_quota.rs:162,230` joins `Value::Blob` by byte equality. Frozen `Map` keys are independently allocated Uint8Array objects from separate reads and compare by identity, never by contents. This violates “Rust 200 ⇒ bytes equal”, independently of sort pair order.
Reproduce: insert credential `(id=X'3132',provider='a',label='x',auth_type='api_key',enabled=1,tier=1,weight=1,created_at=1,updated_at=1)` and a quota window/sample with `credential_id=X'3132',window_type='daily',used=1,limit_value=10,observed_at=1794612000000` (window starts_at=0). With a valid client session, TS returns `{"accounts":[]}` / `{"samples":[],"truncated":false}`; Rust returns the account/sample with `credentialId:{"0":49,"1":50}`. Both status 200. Confirmed against fresh Rust on both routes: `fix-blobid.ts`, `blobid-client-{quota,history}.log`. Match JS key equality, including object identity, rather than SQL-cell structural equality; add both route regressions.

**R2 — NaN timestamp comparisons are neither a total order nor engine-independent.** `crates/omni-control/src/client_quota.rs:172–179` feeds subtraction-with-NaN-as-equal to Rust `sort_by`; the earlier sort at :149–156 has the same general hazard.
