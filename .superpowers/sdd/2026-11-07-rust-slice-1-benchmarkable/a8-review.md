# A8 independent review — request changes

Reviewed the supplied brief, first 60 report lines, both complete diffs, and the frozen route/control/store implementations and session helpers. OAuth merge hunks excluded. No product checkout edits or subagents. Evidence below is under `/tmp/opencode/a8-review/`.

## Important findings

**I1 — malformed credential metadata leaks into Rust logs.** `crates/omni-control/src/credentials.rs:32–50` propagates the JSON parser's input-bearing message; `crates/omni-gateway/src/admin_routes.rs:173–178` logs it verbatim. The parser includes identifiers from the stored value (`crates/omni-ir/src/jsc_json.rs:293–297`).
- Reproduce: set a credential's `provider_data='providerDataSecretCanary'`, log in with any valid gateway key, GET `/api/client/quota` (history uses the same validator). Rust logs `admin route failed reason="JSON Parse error: Unexpected identifier \"providerDataSecretCanary\""`; TS emits no such log. Neither response leaks it: both are 500 with exactly `{"error":{"code":"INTERNAL","message":"internal error"}}`.
- Confirmed by `secret-driver.ts`, `secret/client-quota-rust.log:13`, and the corresponding TS log and response JSON. The ordinary driver still passes: 3,847 equal, zero failures. Sanitize client metadata failures before logging; retain the generic wire response. Add a provider-data canary and scan logs as well as error responses.

**I2 — eager sort-key validation changes successful quota responses into 500s.** `crates/omni-control/src/client_quota.rs:110–117,265–272` requires every sort field to be text before sorting. TS only invokes `localeCompare` when its comparator reaches that field; a one-element array never invokes it at all (`packages/control/src/quota/headroom.ts:180–184`, `clientHistory.ts:123–128`).
- Reproduce: one surviving quota window/sample, credential `label=X'3132'`, normal text provider/id/window. Authenticated GET `/api/client/quota` or `/api/client/quota/history`: TS 200 includes `"label":{"0":49,"1":50}`; Rust 500 INTERNAL. For history, place the single sample inside retention with positive limit. The same eager check also ignores comparator short-circuiting between different providers.
- Confirmed separately for both routes: `probe.log` and `edges-client-history.log` contain exact exchanges. Preserve TS's lazy comparison/coercion semantics, not whole-row prevalidation; cover singleton and short-circuited malformed sort fields.

**I3 — quota cell readers reject invalid UTF-8 instead of matching Bun's replacement decoding.** `crates/omni-store/src/credentials.rs:579–580` and `crates/omni-store/src/quota.rs:93–94,101–102` decode cells through `r.get::<_, Value>`, whose TEXT conversion rejects invalid UTF-8. This bypasses the lossless/replacement handling used by other client readers.
- Reproduce: one quota window with an existing credential; `UPDATE credentials SET label=CAST(X'ff' AS TEXT) WHERE id='single'`; authenticated GET `/api/client/quota`. TS 200 serializes a replacement-character label; Rust 500 INTERNAL, logging `invalid utf-8 sequence ... at index 1`.
- Confirmed in `utf8.log` and `utf8/client-quota-rust.log:49`. The same account reader serves history. Decode TEXT from `ValueRef` with Bun-compatible replacement while preserving BLOB identity; audit both new quota-row readers too.

No Critical finding; no cross-key response leak or session bypass demonstrated.

## Verdict by requested point

1. **Authorisation: pass, with stated coverage limits.** All five GET handlers call `require_client` before query extraction/report-lane acquisition (`client_routes.rs:10–66`). Login necessarily parses before authenticating; logout intentionally accepts anyone. Verification itself reads the key's revocation/expiry through the separate auth connection. Admin/viewer/anonymous/revoked/expired-key/expired-session cases pass; tampered and unknown-instance-shaped tokens also pass added probes. A real token transferred between two live instances was inspected through the per-instance in-memory KV design, not separately exercised. There is no independent enabled/disabled API-key column in this model; revocation is its disabling state.
   Sessions contain only expiry and `{kind:"client",apiKeyId}` under `sess:client:sha256(token)`; 32 random bytes become 43 base64url characters. Neither TS nor Rust compares a raw cookie with a stored plaintext secret: both hash then KV-lookup. Cookie is `omni_admin`, Path=/, HttpOnly, SameSite=Strict, Max-Age=43200; Secure follows configured HTTPS or first forwarded-proto hop. Logout deletes the matched session, clears the cookie, and can end an operator session too, as TS does. Shared operator gates accept only admin/viewer; client access to `/api/keys` is directly tested.
2. **Isolation: pass.** Summary binds session id; logs overwrite scope after forwarding only ten allowed filters (`logs.rs:140–162`); usage forwards five and always calls the optional-scope helper with `Some(id)` (`reports.rs:40–57`). Store queries retain the scope alongside cursors and dimensions. Credential grouping is refused; apiKey grouping remains scoped. Identity/duplicate/encoded/case attacks and foreign client/operator cursors pass; added `keyId`, `key`, and another key's model filter pass. Removing the log scope in scratch makes the stock driver fail, then independent marker checks expose A/C data to B (see verification).
3. **Disclosure: pass on field selection; parity failures I2/I3.** All client projections are explicit allowlists. Summary: id,label,prefix,modelAllowlist,limits,limitUsage,bodyLoggingOptOut,createdAt,revokedAt,expiresAt,guardrailPolicy,smartRouting,dayOffsetMinutes. Usage array rows: key,requests,inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens,rtkSavedTokens,rtkAppliedRequests,costUsd,errors,durationMsSum, plus split when requested.
   Logs: id,state,at,requestedModel,resolvedProvider,resolvedModel,attempts,status,errorCode,inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens,ttftMs,durationMs,costUsd,degradations,rtkApplied,rtkEstimatedTokensSaved; envelope logs,nextCursor. All `excluded:` degradations removed. No credential ids, account labels, other key names, bodies or wider operator diagnostics are appended.
   Quota envelope accounts; row credentialId,label,provider,windowType,usedRatio,resetsAt,observedAt,windowMs,ratePerHourRatio,exhaustsAt,survives,stale,rolledOver. History envelope samples,truncated; row credentialId,label,provider,windowType,observedAt,usedRatio,resetsAt,windowMs. These match TS exactly. Shared provider-account disclosure, including disabled accounts, is the accepted decision; no objection within this parity increment.
4. **Secrets: fail I1.** Credential reads use id,label,provider (tier only for ordering), plus provider_data for whole-list validation. No access_token, refresh_token, api_key or id_token column is selected by these client quota paths. Parsed provider_data is discarded; wire errors stay generic, but malformed content reaches Rust logs. Existing canaries prove response safety for the three seeded token/key values, not metadata/log safety.
5. **Validation/edge parity: fail I2/I3; other probes pass.** Independently checked empty/non-numeric/negative/fractional/huge limits, cursors, bounds, reversed bounds, repeated parameters and case/encoding variants. Extended logs: 829 equal, zero failures after correcting scratch expected statuses and removing nondeterministic live-traffic rows. Non-ASCII/mixed-case ordering and numeric/BLOB cases pass the stock driver. Independently verified history 49,999→49,999/false, 50,000→50,000/false, 50,001→50,000/true, and 50,002 overflow, byte-equal. The flag is one top-level boolean.
6. **Resource bounds: qualified pass, not an absolute per-request bound.** Report work owns the four-permit read-only lane through cancellation; it does not hold the control connection. Logs cap at 500; history reads at most 50,001 raw samples and retains at most 50,000 descriptors plus accounts/output. Usage writes buckets directly, but its SQL aggregation and output size grow with retained matching data/distinct groups. Quota accounts/windows and metadata reads are also database-sized, not fixed-count capped; joins scan accounts per sample/window. Thus “no unbounded work” cannot literally be claimed independently of database size. These are TS-parity behaviours, not a demonstrated new divergence. The accepted unbounded waiter queue is materially more exposed to less-trusted key holders than to operators; four running readers do not bound queued requests.
7. **Tests: credible but incomplete.** Comparisons are normalized wire-byte comparisons (date/random session token/validated content length masks), with separate expected statuses and isolation scans. Reported RED counts were read, not rerun historically. Mutation proof succeeds: stock driver fails on client/operator cursor disagreement; bypassing only that scratch precheck yields 84 failures and explicit B-response A/C marker leaks (`mutant-markers.log:1278+`). All seven surface routes are equal, not expected divergences. Existing secret scans cover quota/history responses including errors, but not every route's credential canaries, provider_data, id_token or logs; I1 escaped them. Existing history fixture used 50,002 rows, not exact-cap tests; independent probes supplied those.
8. **Safety/dependencies: pass by inspection.** No A8 unsafe or dependency addition. New indices address fixed-width SQL rows or indices derived from their vectors; history arithmetic uses floats and a constant cap. Summary's `stringify(...).expect("summary")` is reachable but its argument is always an object, so no input-dependent None/panic found. No caller-controlled integer overflow found. Full workspace tests/Clippy were not rerun.
