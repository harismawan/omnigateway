## Findings
- **Critical / Important: none demonstrated.** No differing output excerpts exist.
- **Minor — eager empty-read allocation:** `crates/omni-store/src/quota.rs:140-141` reserves 50,001 pairs and five-cell arrays before SQL execution, even with no matches. Repro: migrated DB, `DELETE FROM quota_samples;`, query `since=1794614400001`; old=new `{"samples":[],"truncated":false}`. Generator `ranks-0.sql` also reproduces this.
- On this 64-bit layout, five 32-byte Values plus a 16-byte pair reserve **8,800,176 bytes/request (~8.39 MiB)**, versus zero sample-vector backing allocation for an empty old read. This is capacity/allocator pressure, not a measured RSS increase; untouched pages need not become resident.
- `client_routes.rs:11-17` authenticates then obtains the reader; `admin_routes.rs:76,125-142,153-159` admits four readers and retains permits through blocking work. Thus empty-page reservation peaks at **35,200,704 bytes (~33.57 MiB)** across admitted histories, not unbounded per waiting request. Consider lazy/smaller initial reservation if sparse-history traffic matters; this bounded tradeoff does not block approval.
- Full-page total memory has no fixed byte bound before or after: text/blob lengths, metadata and completed response buffers are variable; old also allocated seven owned cells per row, per-row Vecs and sort keys. The 33.57 MiB figure is only the new fixed reservation component, not total process memory.
## Read-only reasoning
- Reader callers: production compact reader only history (50,001); tests use 50,001 and 10; benchmark uses 50,001. Old reader has no remaining production caller. Public usize limit casts to i64 in both readers; reservation cap does not itself cap returned rows for an arbitrary caller.
- No cheap 64-bit hash collision constructed. Collision equality explicitly checks SQLite type tag and complete original bytes (`quota.rs:159-167`), with integer bits/real bits including signed zero; lossy UTF-8 ownership cannot merge distinct raw keys. Thousands of distinct cells tested. Account reverse lookup remains O(samples×accounts), already present before optimization.
- Preliminary ordering is UTF-16, not locale; ASCII fast path preserves it. Final locale-equivalent keys share ranks, with stable numeric timestamp sorting. Scatter is stable; width>64 fallback is stable. New indexing uses internally constructed ids/ranks and bounded group width.
- `compare_numbers:74-80` checks both NaN flags before `expect`; text-derived NaN cannot reach the expect arm. No added log statements. Settings/read errors still precede metadata errors; locale validation still follows metadata validation. Preliminary sort/trim moved before metadata validation, adding work on invalid metadata but no newly fallible semantic operation found.
- Direct writer retains the same JS number formatter, string escaping semantics and blob value-tree fallback; differential coverage exercised each path.
