## Seven verdicts
1. **Fairness — sound, with explicit scope caveats.** CLI credentials/model declarations, request bodies, CPU sets, warm-up and deterministic scenario order are shared. `taskset` and the Rust launcher both exec, preserving the sampled PID (`bench-gateway.ts:254–262,528–535`; `run-rust-gateway.sh:14`). Live `/proc` checks identified each actual binary, affinity `0-3`, threads and no child processes. Process CPU includes threads; child processes would be excluded equally. RSS uses identical `/proc/statm` sampling every 100 ms after warm-up, then identical settle sampling; it is sampled resident memory, not allocation totals or guaranteed instantaneous peak. One process serves successive scenarios, so later RSS includes earlier workload history. Rust alone gets production-launcher `MIMALLOC_PURGE_DELAY=1` (`run-rust-gateway.sh:6–7`); disclose that policy, not an allocator-neutral language comparison. Ambient environment is inherited and not fully recorded. Rust's writer barrier is enabled via shared `OMNI_BENCH=1`; TS uses row accounting instead. CPU sampling ends before the final writer barrier, so deferred persistence CPU can escape the interval (`bench-gateway.ts:1081–1115`); this inherited limitation needs disclosure or measurement through drain.
2. **Integrity — not sound.** Smoke rejects malformed/empty streams and explicit SSE errors, and HTTP load failures/log deficits/pending rows/writer failures are checked. But measured bodies and semantic request-log outcomes are not validated. Both gateways accepted empty-load reproduction below; successful logging is not successful inference. Load-failed scenarios also retain metrics. Even smoke checks only one matching text fragment plus a terminator, not the complete expected output or usage.
3. **Upstreams/capacity — not sound as a complete realism/ceiling claim.** Shared fixtures exercise decode/translation and supply usage; Anthropic start/block/delta/stop ordering is coherent. Pre-encoded repeated deltas apply identically to both gateways; no gateway-dependent shortcut found. Responses omits normal lifecycle events (see minor below). Capacity driver uses two pinned stub processes, persistent oha connections and real TLS for Messages; direct `--insecure` changes certificate validation only, not gateway verification. However it uses concurrency 64 for both chunk sizes, versus 16 for long-stream gateway runs (`bench-upstream-check.sh:27–28`); repeat at matched concurrency, CPU sets, release binaries and quiet-host conditions. Existing busy-host/dev-binary evidence cannot establish the requested release-gateway margin. I did not measure capacity. Legacy chat behavior is unchanged without `--matrix`: same enqueue boundaries; old/new payload checks matched after normalizing the pre-existing random UUID (literal independent responses naturally differ).
4. **Default path — sound.** Scenario-definition block is byte-identical to base. Ran all ten default TS scenarios with short durations and `--streams 16`; names and top-level/per-scenario JSON keys match `docs/benchmarks/2026-11-08-rust-slice1.json` runs[0]. No matrix fields leak into default output. Payload comparison covered instant one/2,000 chunks and delayed three chunks.
5. **Comparison — not sound for conclusions yet.** Median (including even counts), min–max, inclusive overlap and lower-is-better direction are correct. Explicit failed/unsupported observations suppress ratios; unequal counts are printed; missing/mixed SHA256 identities are refused. But single observations count as better/worse, missing observations can silently enter comparisons, and workload/configuration compatibility is unchecked. At least **two successful observations per side** are needed for a nontrivial observed range; use the documented five or more for reporting, and never call min–max overlap a significance test.
6. **Interleaved runner — sound for its documented fail-fast behavior.** AB/BA alternates correctly. Load guard is checked only once at startup, not before each round (`bench-rounds.sh:11–15`); before/after samples do not enforce quietness. Existing round JSON is protected. A failed round exits immediately under `set -e`: no subsequent rounds or comparison; reproduced below. No partial-data summary is automatically published. Individual after-file is missing on failure, but global host-after trap runs. A later manual comparison has no expected-round manifest and can accept incomplete directories. Reusing an output directory can overwrite host metadata/logs without JSON, append commands, or leave an old comparison; require fresh OUT.
7. **Namespace/OAuth — sound for the seeded no-refresh case.** Affinity demonstrably survives the namespace; `/proc` sampling and oha worked. Wrapper adds trust via `NODE_EXTRA_CA_CERTS`/`SSL_CERT_FILE`, with no verification-disable switch (`bench-matrix.sh:11–12`); OAuth TLS scenarios passed on both binaries. Seed uses PBKDF2-SHA256/AES-256-GCM, 12-byte IV and separate 16-byte tag in `enc:v1` format (`bench-oauth.ts:5–35`), matching conformance. Expiry is epoch-ms 2100, safely beyond refresh leads. This is a fixture token accepted by the stub, not a live Anthropic token. Unexpected refresh would add HTTP/crypto/persistence/coordination work and distort CPU/latency; the stub silently serves refresh and the harness does not count/assert zero refreshes (`bench-anthropic-upstream.ts:31–36`). Add that assertion for stronger assurance.
