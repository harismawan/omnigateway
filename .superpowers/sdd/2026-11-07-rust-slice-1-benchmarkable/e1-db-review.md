## Critical / Important findings

**C1 — extra outside-file deletion, `crates/omni-control/src/database.rs:46–48`.** Rust `Path::join` replaces its base for an absolute `rel_path`; Node `path.join` does not. Reproduction: in an initialized DB insert `request_bodies(request_id,at,rel_path,size_bytes,detail_state,truncated) VALUES('x',1,'/tmp/opencode/db-review/probe/outside',4,'ready',0)`, create that outside sentinel, then `--root /tmp/opencode/db-review/probe --db db db clear-bodies --yes --json`. Both report removed=1/orphans=0/exit=0; TS preserves the sentinel, Rust deletes it. Match Node's joining/normalization before unlinking; add this destructive regression. `probe.py`/`probe.log` reproduce it.

**I1 — unreadable pidfile bypasses a TS refusal, `crates/omni-cli/src/status.rs:54`.** Create `$XDG_STATE_HOME/omnigateway/gateway.pid` containing a live PID, chmod it 000 as an ordinary user, then restore a valid candidate. TS stops with `EACCES: permission denied, open '<pidfile>'`; Rust's `.ok()` treats it as absent and proceeds to candidate validation/confirmation. Demonstrated with an absent candidate: Rust instead reports `BAD_REQUEST: no such snapshot`. Particularly important before enabling the swap. Propagate read errors as TS does; this differs from the explicitly accepted signal-zero/other-user decision.

**I2 — filesystem adapter semantics differ, `crates/omni-control/src/database.rs:137,317–321,523–531`.** Frozen `packages/control/src/nodeFs.ts:60–74` swallows *all* readdir/stat failures. (a) chmod snapshots 0300 and run backup: TS succeeds, Rust exits 1 with EACCES/scandir **after writing a complete snapshot**. (b) restore a syntactically valid ID under snapshots chmod 000, a self-referential candidate symlink, or an ID with a 300-letter reason: TS says `BAD_REQUEST: no such snapshot`; Rust says EACCES/stat, raw ELOOP, or raw ENAMETOOLONG respectively. All reproduced. Preserve the frozen adapter behavior rather than merely formatting the propagated errors.

**I3 — refusal-state coverage is overstated, `conformance/cli/db-vacuum.ts:19–23`, `db-backup.ts:111–114`, `db-clear-bodies.ts:25–33`.** Vacuum checks only live-file bytes, not sidecar presence/bytes or snapshots; the backup bad-key branch leaves seeded snapshot bytes/listing unchecked; clear-bodies seeds/checks no snapshots. None of these suites establishes the requested full refusal-state invariant. Restore does substantially better, but lacks nonempty-WAL refusal fixtures. Add shared full-state assertions to both executions and the permission/path cases above; otherwise the passing matrix cannot establish the stated destructive-command guarantee.
