## Findings

**Critical C1 — post-confirmation containment validation omitted (`crates/omni-control/src/database.rs:366–375`).** Frozen `restoreSnapshot` calls `snapshotPath` AGAIN, including grammar and realpath containment; Rust only joins/stats/inspects. Reproduction: start restore in a PTY with a valid candidate; at `[y/N]`, replace `snapshots/<id>` with a symlink to a valid database outside snapshots, then answer y. TS: exit1 `BAD_REQUEST: invalid snapshot id`, no undo/install. Rust: exit0, writes undo and installs the outside database. Observed in `probes.py`, case `symlink-change`. Share full path validation between preview and swap; content reinspection alone is insufficient. Public Rust restore_snapshot also accepts arbitrary unchecked IDs directly.

**Important I1 — accepted SQLite hash values cause Rust-only failed restores (`crates/omni-control/src/database.rs:465–472`).** Frozen `readRaw` returns the SQLite value without runtime string validation; Rust requires String. Reproduction: candidate initialized normally, `INSERT INTO settings(key,value) VALUES('adminPasswordHash',X'616263')`, restore --yes/accepted PTY. Both validate/install candidate and retain undo; TS succeeds exit0 with changed-hash result, Rust exits1 `Invalid column type Blob at index: 0, name: value` after installation. Same issue before copy if the live hash is BLOB. Preserve frozen value/equality behavior, including BLOB identity semantics, rather than adding a type refusal after the destructive step.

**Important I2 — advertised FULL post-state comparison is not full (`conformance/cli/db-file-state.ts:13–14,25–32`; `db-restore-swap.ts:100,130–137`).** Helper enumerates only db/-wal/-shm, snapshots and request_bodies; it omits `.incoming`, journals and every other root entry. Concrete negative test: point OMNI_CLI_BIN at scratch wrapper that runs the correct binary then writes `<--root>/unexpected-swap-file`. **All seven swap cases + five round trips still PASS.** This disproves the claimed whole-root invariant. Incoming absence is separately checked for the first swap, but round trips compare only exit, logical rows and undo count—not stdout/stderr/full post-state. Capture all root entries before opening inspection handles, compare round trips too, and add a mutation that must fail.

**Minor M1 — “exact sequence” test pins a different ordering (`database.rs:389–392,652–653`).** TS writeSnapshot calls freeBytes before stat(live); Rust reverses them. Static outcome generally agrees, but the asserted seam sequence is not exact and fault/race ordering differs. Swap also duplicates forced snapshot construction instead of using tested write_snapshot; the separate forced-undo unit does not exercise that duplicate.

**Minor M2 — filesystem modes untested (`db-file-state.ts:5–10`).** lstat is used for type only; modes are never compared. They matter: candidate chmod0444 is copied/installed as0444, then reopen fails on both CLIs (observed). Include mode bits for files/dirs; do not assume “no explicit chmod” means no copy-mode effect. No mode divergence demonstrated.
