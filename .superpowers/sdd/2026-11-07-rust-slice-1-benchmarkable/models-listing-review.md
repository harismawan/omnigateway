## Important — credential auths are rebuilt and narrowed once per credential, per target

Frozen `packages/control/src/modelLimits.ts:129–143` builds a provider-to-auth **Set** once per model, then `targetLimits:80–81` visits at most two auths. Rust `crates/omni-router/src/model_limits.rs:40–45,55–62` scans all credentials and allocates a Vec for each target, retaining duplicates, then narrows for every duplicate. Independent HTTP measurement, 5,000 enabled OpenAI credentials (half each auth), 500 models × 4 OpenAI targets, 20 warmups + 100 sequential requests: baseline median **0.883 ms**, p95 **1.153 ms**; final median **373.691 ms**, p95 **392.869 ms**. Same seeded DB, private HOME, ports 19710/19711, debug binaries identified by supplied SHA256; no provider traffic. Responses are the expected old-vs-new listing bodies (`latency/{baseline,final}/body.json`), not semantic counterexamples. Fix by deduplicating enabled auth types and indexing resolvable pins once per model (or listing) as frozen does. Cost is synchronous on the request task. Evidence: `latency/results.json`, seed DB and bodies, `latency-measure.exit`.

Frozen binary on the **same** fixture: median **83.912 ms**, p95 **93.717 ms**, 100 measured requests after 20 warmups (`latency/ts-results.json`). Final is **4.45× frozen**, **423× baseline** median. Frozen and final return the **same 95,578 bytes** (`latency-body-compare.exit`: `cmp frozen/final latency response bodies: 0`). This is a cost finding, not a claim their bodies differ. Reproduction input: `latency/seed.db`; API key `sk-omni-review`; models `m000` through `m499`, four identical `{provider:"openai",model:"gpt-6.1-sol",...}` targets each with no saved figures/pins; 5,000 OpenAI accounts with empty providerData, no secrets, alternating apiKey/oauth. Frozen body → `latency/ts/body.json`; Rust body → `latency/final/body.json`. Both advertise each model's own id as display name and `272000`/`128000`. A 23 KB response-size increase cannot explain the ~373 ms increase; frozen emits those same larger bytes in ~84 ms. Baseline/final requests were sequential in one otherwise shared host, not a dedicated benchmark machine; debug-vs-release absolute times are not established. Repeated samples are tight enough to establish this regression, and source proves unnecessary per-credential work.
