# Gateway: Rust slice 1, single process

Fresh round-3 measurements at **`30661f94d2ea3f8b5f685d69525163632b84fd40`**. Three full uncapped runs; **30/30 scenarios have coherent barriers and zero dropped, failed, missing or pending events/rows; zero crashes**. Raw runs and independently computed median/min/max metrics are in [the JSON](2026-11-08-rust-slice1.json). Previous measurements are not mixed into these results.

## Method

Three sequential foreground full uncapped runs, 20s after 3s warmup; gateway 0-3, upstream 4-5, oha 6-7; release fat LTO, one codegen unit, panic=abort, mimalloc. OMNI_BENCH=1; coherent epoch-prefix barrier deltas, then request-row accounting. No --rate. Each numeric summary leaf independently median/min/max, not a representative run.

```sh
OMNI_BENCH_KEEP=1 bun scripts/bench-gateway.ts --gateway target/release/omnigateway --cli 'bun apps/cli/src/index.ts' --gateway-cpus 0-3 --upstream-cpus 4-5 --load-cpus 6-7 --out /tmp/opencode/task6-round3/runN.json
```

Build: `cargo build --release -p omni-gateway`. Same i5-13400 / 8-vCPU KVM Linux rig and pinning as the [TS baseline](2026-11-07-ts-baseline.md). TS numbers below come from that baseline, not a new TS performance run. TS conformance binary was freshly rebuilt with `bun scripts/build-binary.ts /tmp/opencode/e2e/ts-omnigateway`.

Before each run, two top samples showed an idle host without competing sustained CPU load; complete snapshots are embedded in JSON. No unrelated processes were terminated. Bench roots were retained until logs, body fixtures, database row-count/schema/file-size evidence and complete JSON were extracted, then freed. Artifacts: `/tmp/opencode/task6-round3/`.

The bench-only `POST /__omni/bench/flush` uses lock-free producer epoch accounting. The barrier asynchronously settles prior entrants and reports exactly the resolved epoch prefix: committed + failed + dropped = watermark. Seeds are accounted separately. Single-flight, nonblocking queue admission and server deadline remain; 409/503/504, timeout or incoherence means inconclusive, never zero. Scenario deltas include warmup. Production has no barrier endpoint unless `OMNI_BENCH=1`. Non-held/non-cancel requests have a 30s timeout.

## Held-streams and compatibility

Full-run peak **72.02 (71.34–76.13) MiB**, below the actual **80 MiB RSS** target in all three. Fresh-process isolation: **57.84 MiB**, one run, separately recorded; zero loss. Full-run heap history matters; isolation does not replace the full-run measurement.

Minute history is configuration-independent, equal-ms run-length compressed, capped at 65,536 exact entries then fixed 1s END-expiring buckets (at most 61 overlapping minute buckets). Ordered finite traffic overcounts by at most the trailing bucket; clock rollback deliberately over-refuses. Ambiguous clamped forget debt may prolong over-refusal indefinitely under continuous traffic. Long-window newest capped seed stamps match debit eviction; exact reset differences can persist below cap until omitted history expires. See [limiter compatibility](../limiter-compatibility.md). No claim of universal exact TS reset parity. Fixed-limit/configuration-change real-TS tests and binary e2e pass.

Rust request IDs deliberately differ: `req_` + RFC 9562 UUIDv7 versus TS UUIDv4. Process-monotonic method-3 random increments hide exact intervening counts but permit statistical rate estimates and expose mint time. The 48-bit timestamp boundary is year 10889. The process-global CSPRNG is fallibly OS-seeded at boot; failure refuses startup. ID derivations retain their shape; e2e verifies TS v4, Rust v7 and timestamp bounds.

## Eight-producer contention comparison

Same current writer_throughput eight-producer test copied into git archive c50977ff (pre-round2, no blocking RwLock), both taskset 0-3. 8 spin-paced 125us producers, v4-shaped Begin-only rows, 5s nominal; XBARRIERS unset or 1. Both revisions shed in this synthetic v4 Begin-only workload. Eight spin-paced producers oversubscribe four cores shared with SQLite; the ~64k send rate is imposed by pacing, not a capacity result. With continuous barriers, the test checks its 5s stop only after flush returns, so final runs substantially longer and accumulates more drops. This is a measured limitation/regression concern, not evidence of improved contention throughput; scheduler-sensitive maxima are not pure lock latency. An earlier uninstrumented repetition is retained in the artifact logs. The gateway’s actual v7 Begin/Finish workload is the separate zero-loss full-run evidence above. No inference from old single-core capacity figures.

Writer configuration: batches 4096, queue 131072 (~1.18s at 55.4k requests/s × 2); slots ~360B each (~45MiB full), plus owned payload strings. Fixed-row prepared statements and no read-back; checkpoint thread. `wal_autocheckpoint=10000` is a trigger, not a WAL size bound under pinned readers.
